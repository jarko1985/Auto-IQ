## Architecture

Modular monolith with explicit domain boundaries. Each domain in `features/` owns:

- Zod schemas / DTOs
- Service layer (business logic)
- Repository / Prisma access
- Authorization rules
- Tests

**Dependency direction (strict):**

```
UI → application services → domain rules → repositories / external adapters
```

**External provider interfaces** (never couple to SDK directly):

- `AIProvider` · `PaymentProvider` · `EmailProvider` · `SmsProvider` · `StorageProvider`

**i18n:** `app/[locale]/` for all user-facing routes. `en` default, `ar` supported. RTL via `dir` attribute on `<html>`. Messages in `messages/{locale}.json`.

**API base path:** `/api/v1` — JSON only. Success: `{ data, meta }`. Error: `{ error: { code, message, details, requestId } }`.

## Rules — Non-Negotiable

1. **No `any`** — use discriminated unions, generics, or `unknown`.
2. **Server-side auth on every protected action** — never trust client role/price/total.
3. **Zod validation at all boundaries** — API inputs, AI outputs, env vars.
4. **Money in integer minor units** — never floating-point. Currency always explicit.
5. **AI is probabilistic** — never guarantee a diagnosis; never let AI write DB/payments.
6. **Provider abstraction** — AI, payment, email, SMS, storage behind interfaces.
7. **Audit trail** — financial, booking, repair, and auth events must be logged.
8. **No secrets in client code** — zero `NEXT_PUBLIC_` on sensitive vars.
9. **UTC timestamps everywhere** — `createdAt`, `updatedAt`, `deletedAt`.
10. **Safety rules beat AI** — critical symptoms (brake failure, oil pressure, fire) override model output in deterministic code.

## Hardening: RTL Layout Support (ahead of Sprint 19)

Prompted by scoping Sprint 19 (Arabic-Native AI Reasoning) — that sprint fixes what _language_ the AI's own output comes back in, but a review of the surrounding UI chrome found the app had only ever set `dir="rtl"` on `<html>` (Sprint 0) and never actually audited whether components rendered correctly under it. A full sweep of `app/`+`components/` (199 `.tsx` files) found two categories of real RTL bugs, both fixed:

- **Physical CSS properties that don't respect `dir`**: 42 files used `marginLeft`/`marginRight`/`paddingLeft`/`paddingRight`/`borderLeft`/`borderRight`/`textAlign: "left"|"right"`/absolute-position `left`/`right` — all hardcoded to one physical side regardless of reading direction, which is invisible in LTR but produces misaligned icons, wrong-side padding, and backwards-reading text alignment under RTL. Fixed by converting every instance to the CSS **logical property** equivalent (`marginInlineStart`/`marginInlineEnd`, `paddingInlineStart`/`paddingInlineEnd`, `borderInlineStart`/`borderInlineEnd`, `insetInlineStart`/`insetInlineEnd`, `textAlign: "start"|"end"`) — these respect `dir` automatically via the browser's own writing-mode handling, so no JS/locale-detection is needed at all for pure layout. Also fixed one shadcn primitive (`components/ui/alert-dialog.tsx`) using the Tailwind physical class `sm:text-left` → `sm:text-start`.
- **Directional icons don't auto-flip**: an SVG chevron/arrow's visual direction is fixed regardless of `dir` — 14 files used `ChevronLeft`/`ChevronRight`/`ArrowLeft`/`ArrowRight` (lucide-react) for "back"/"next"/"forward" affordances (wizard step navigation, prev/next-week calendar controls, form submit buttons, "back to X" links) that need to visually point the way reading flows, which flips under RTL. Fixed with a new `i18n/direction.ts`: `isRtlLocale(locale)` (pure, usable anywhere a locale string is in hand) and `useIsRtl()` (client-component hook, wraps next-intl's `useLocale()`). Client components swap icons with `const ForwardIcon = useIsRtl() ? ChevronLeft : ChevronRight`; the 3 server-component pages needing this use `isRtlLocale(await getLocale())` instead (`useLocale()`'s hook form is client-only in this codebase's existing convention — see "Server components" below).
- **Local dev database swap (unrelated to RTL, done in the same session)**: Docker Desktop stopped working on this machine (`Wsl/Service/CreateInstance/CreateVm/HCS/ERROR_NOT_SUPPORTED`, traced to `Win32_Processor.VirtualizationFirmwareEnabled: False` — Intel VT-x disabled in BIOS, not a Docker/WSL software issue — confirmed by `wsl --update` refreshing the kernel with no change). Rather than block on a BIOS fix, local dev's `DATABASE_URL`/`DIRECT_URL` were switched from the Docker-Compose Postgres to a free-tier Neon project (via Vercel's Storage/Marketplace integration, Neon Auth left off since this app has its own complete Auth.js system) — schema pushed, HNSW vector index created, seed re-run, all verified against the live Neon instance. **Both `.env` and `.env.local` needed updating** — Next.js loads `.env.local` with higher priority than `.env`, and a stale `.env.local` silently kept the dev server on `localhost:5432` even after `.env` was correctly updated, which is what "database unreachable" errors mid-session turned out to be. `docker:up`/local Postgres remains the documented default (`.env.example`, `npm run docker:up`) for other environments; this machine currently runs against Neon as a substitute.

Verified against the **live dev server and the new Neon database** (not just static checks): `typecheck`/`lint`/`build` all clean, full unit test suite (323 tests) passing, and real HTTP fetches of `/ar/sign-in`, `/ar/dashboard`, `/ar/diagnostics/new` all returned `dir="rtl"` with the converted logical CSS properties (`inset-inline-start`, `padding-inline-end`, `margin-inline-start`, `text-align:start`) present in the rendered HTML; confirmed the directional-icon swap live by checking the rendered SVG's lucide class name — `lucide-arrow-left` under `/ar/sign-in` vs. `lucide-arrow-right` under `/en/sign-in` on the same submit button.

## Known Conventions (accumulated)

- **Middleware:** `proxy.ts` not `middleware.ts` — Next.js 16 renamed the convention.
- **UI layout:** Use inline `style={{}}` props for page-level layout/centering — Tailwind v4 flex centering has edge-case issues. Tailwind classes are fine for color, typography, and spacing _within_ components.
- **shadcn Card:** Avoid `Card`/`CardHeader` for page layout — `@container/card-header` applies CSS size containment that collapses layouts in Tailwind v4. Use plain `<div>` with inline styles instead.
- **Dynamic routes in `router.push`:** Cast to `as any` — `typedRoutes: true` doesn't handle runtime-constructed paths.
- **Server components:** Use `getTranslations` (async) not `useTranslations` in server components.
- **Storage:** `lib/storage/` — `StorageProvider` interface (`upload`/`download`/`delete`/`getUrl`), `ConsoleStorageProvider` in dev persists bytes to a local gitignored `.local-storage/` directory (Sprint 16 — previously discarded uploaded bytes entirely). Knowledge documents still keep their own `extractedText` column independent of storage, since PDF re-extraction isn't implemented regardless of persistence. Real S3/Blob provider still not implemented — no sprint has required it yet.
- **Seed password:** All dev users share `DevPass123!`.
- **Auth layout:** `(auth)/layout.tsx` renders `{children}` only — each auth page wraps itself in `AuthSplitPanel` (`components/layout/auth-split-panel.tsx`). Media queries injected via `<style dangerouslySetInnerHTML>` in the client component.
- **Vitest env:** `vitest.config.ts` sets dummy `DATABASE_URL` / `AUTH_SECRET` via `test.env` so any test importing `lib/env.ts` (directly or transitively) doesn't need a real `.env` loaded — Vitest does not auto-load `.env` files.
- **AI provider abstraction:** SDKs (`openai`, `@anthropic-ai/sdk`) live only in `lib/ai/providers/` — never import them in client components or route handlers. Business logic (prompt versioning) lives in `features/ai/`; `lib/ai/` stays domain-agnostic (no `DiagnosticResult` types).
- **Customer sidebar:** `components/layout/customer-sidebar.tsx` — 240px sticky navy sidebar, active route detected with `usePathname()`. Injected in `(customer)/layout.tsx`.
- **RTL layout:** Use CSS logical properties (`marginInlineStart`/`End`, `paddingInlineStart`/`End`, `borderInlineStart`/`End`, `insetInlineStart`/`End`, `textAlign: "start"|"end"`) instead of physical `left`/`right` in every new inline `style={{}}` — they respect `dir="rtl"` automatically, no locale check needed. Directional icons (back/next chevrons, forward arrows) don't auto-flip and need explicit handling: `useIsRtl()` (`i18n/direction.ts`) in client components, `isRtlLocale(await getLocale())` in server components.
- **Local dev database:** currently a free-tier **Neon** project (`DATABASE_URL`/`DIRECT_URL` in both `.env` and `.env.local` — Next.js prioritizes `.env.local`, so both must match or the dev server silently uses the stale one), not Docker — Docker Desktop is broken on this machine (BIOS-level VT-x disabled, not a Docker bug). `docker:up`/local Postgres is still the documented default elsewhere; don't assume it's what's actually running here without checking `.env.local` first.
- **Email provider:** `lib/email/` — `EmailProvider` interface, `getEmailProvider()` picks gmail vs. console off `EMAIL_PROVIDER`. Real Gmail SMTP is configured on this machine (`.env`/`.env.local`'s `GMAIL_USER`/`GMAIL_APP_PASSWORD`) — email sends for real here, not just to the console log. Never put a real value in `.env.example`; that file is a blank template.
